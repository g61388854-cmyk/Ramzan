# Резервное копирование и восстановление

## Что копируется
1. База данных PostgreSQL (дела, участники, факты, документы и их версии, журнал действий, справочник).
2. Каталог данных приложения: зашифрованные исходные материалы (`files/`) и экспортированные документы (`exports/`).
3. Ключ шифрования хранилища (`PAI_STORAGE_KEY` из `.env` либо файл `storage.key`). **Без ключа восстановить файлы невозможно.** Ключ хранится отдельно от резервных копий (сейф, носитель с ограниченным доступом).

## Создание копии
```bash
cd deploy
echo '<длинная парольная фраза>' > /secure/backup.pass && chmod 600 /secure/backup.pass
PAI_BACKUP_PASSPHRASE_FILE=/secure/backup.pass ../scripts/backup.sh
```
Результат — `deploy/backups/pai-ГГГГММДД-ЧЧММСС.tar.enc` (AES-256, PBKDF2) и файл контрольной суммы `.sha256`. Рекомендуемая периодичность — ежедневно, с хранением копий вне сервера (не менее 30 суток) и регулярной проверкой восстановления.

Пример задания cron (02:30 ежедневно):
```
30 2 * * * cd /opt/procedural-ai/deploy && PAI_BACKUP_PASSPHRASE_FILE=/secure/backup.pass ../scripts/backup.sh >> /var/log/pai-backup.log 2>&1
```

## Восстановление
```bash
cd deploy
PAI_BACKUP_PASSPHRASE_FILE=/secure/backup.pass ../scripts/restore.sh backups/pai-20261014-023000.tar.enc
```
Скрипт проверяет контрольную сумму, расшифровывает архив, переименовывает текущую БД в `pai_restore_old`, восстанавливает дамп и файлы, перезапускает приложение. После проверки восстановленной системы удалить `pai_restore_old`.

## Восстановление после сбоя приложения
- Незавершённые фоновые задачи (OCR, извлечение) при перезапуске помечаются как прерванные; обработку материала можно запустить повторно кнопкой «Повторить» на вкладке «Материалы».
- Временные файлы, оставшиеся после сбоя, удаляются при запуске (с перезаписью содержимого).
- Сохранённые версии документов неизменяемы, поэтому сбой при редактировании не повреждает ранее сохранённые версии.
